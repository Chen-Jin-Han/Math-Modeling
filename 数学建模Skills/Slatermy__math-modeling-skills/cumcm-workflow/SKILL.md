# 数模国赛通用建模流程与论文写作

这是「数模国赛」skill 家族的顶层入口，负责**通用流程、论文、时间管理**。具体题型方法见：
- `cumcm-a` —— A题（物理/工程/微分方程/数值模拟）
- `cumcm-b` —— B题（优化/运筹/规划）
- `cumcm-c` —— C题（数据/统计/机器学习）

> 竞赛简称：CUMCM（高教社杯全国大学生数学建模竞赛），每年 9 月，3 天 3 夜，本科组从 A/B/C 三题中选一题。3 人一队。

---

## 一、竞赛本质（先想清楚，别一上来写代码）

评阅人看的是：**你把一个实际问题"翻译"成数学问题、再求解、再讲清楚的能力**。得分点按优先级：

1. **模型与问题的契合度**（方向对不对，比算法多高级重要得多）
2. **建模的严谨性与完整性**（假设合理、推导清楚、检验扎实）
3. **论文的可读性与规范性**（摘要、图表、结构、符号）
4. 算法新颖度 / 复杂度（只是锦上添花，切忌堆砌）

**一句话心法：先选题审题，再问题分解，再建模，最后才写代码。禁止"看到数据先跑十个算法"。**

### 拿到题目后：先给三条破题方向（必做）

选定题目后**不要立刻写代码**，先给团队三条可行的破题方向，一条都不能少：

1. **大多数人会走的思路（主流·稳妥）**：题目的"标准解法"，套路最成熟、参考资料最多、最易完整做完。**优点**：稳、不易翻车、保底。**缺点**：同质化严重、难出彩、上限被锁死。
2. **少部分人会选的思路（差异化）**：换个切入点——不同模型族、不同问题重构、不同假设、不同数据用法，或把"大多数人忽略的约束/指标"纳入。**优点**：有区分度、评阅人眼前一亮。**缺点**：需论证"为什么更合理"，参考少，自己扛风险。
3. **难度高但完成好质量很高的思路（冲奖）**：把问题做得更深/更全/更严谨（机理+数据融合、更硬核的约束、更强的验证体系、原创算法）。**优点**：上限最高、冲一等奖。**缺点**：时间成本高、翻车风险大、对团队要求高。

每条方向都用**一句话说清：核心思路 + 为什么可行 + 大致模型/算法 + 主要风险**。团队据此在「保底 / 差异化 / 冲奖」之间做选择，再进入问题分解。

**选择原则**：
- 时间紧 / 队伍磨合一般 / 首次参赛 → 优先方向 1，把它做到 120 分
- 有一项突出优势（算法强 / 专业对口）→ 方向 2 做差异化
- 队伍强 + 冲一等奖 → 方向 3，但必须预留回退方案（做不动就退回方向 1/2 的骨架）

## 二、三天时间规划（默认建议）

| 时间 | 阶段 | 关键动作 |
|---|---|---|
| 第 1 天上午 | 选题 + 审题 | 三题都读一遍，判断自己团队擅长哪类，果断选。选定后**逐字精读**，划出所有条件/数据/问题 |
| 第 1 天下午~晚 | 问题分解 + 模型框架 | 把每问拆成：研究对象/输入/输出/困难/约束/指标/与上一问的关系；画出"问题依赖草图"；确定大方向 |
| 第 2 天 | 建模 + 求解 | 分问题逐个建模型、写代码、出结果；**边做边记论文草稿**（公式、图表、结论随手写进论文框架） |
| 第 3 天上午 | 敏感性分析 + 模型检验 | 参数扰动、方法对比、交叉验证、鲁棒性 |
| 第 3 天下午~晚 | 论文成稿 | 摘要反复打磨、图表规范、参考文献、排版。**摘要留足时间，它是第一关** |

**选题策略**：
- 队里有物理/工程背景 → A 题（机理建模，公式推导）
- 队里擅长运筹/编程/算法 → B 题（规划优化，代码量中等）
- 队里擅长统计/数据分析/机器学习 → C 题（数据驱动，代码量最大但套路最成熟）
- 不确定时：**C 题数据题最容易"保底完成"，A/B 题上限更高但翻车风险大**。

## 三、论文结构（国赛标准八段式）

国赛论文固定结构，**不要缺项**：

1. **摘要**（最重要，占印象分 80%）
2. 关键词
3. **问题重述**（用自己的话简述，不是抄题）
4. **问题分析**（每问拆解思路，画依赖图/流程图）
5. **模型假设**（合理简化，逐条编号）
6. **符号说明**（表格，符号/含义/单位）
7. **模型建立与求解**（核心，按问题分小节：模型→推导→算法→结果→检验）
8. **敏感性分析**（参数扰动后结果变化）
9. **模型评价**（优点、缺点、改进方向）
10. 参考文献
11. 附录（代码、大量数据表、推导细节）

---

## 四、摘要写作（评阅第一关，决定生死）

**评阅人先看摘要再决定要不要细读**。摘要要点：

- **一页以内**，一般 800~1500 字，中文规范
- 结构（固定套路）：
  1. 一句话点题：本文针对 XX 问题，研究 XX
  2. 问题一：用了什么模型 → 什么结论（关键词 + 数字结论）
  3. 问题二、三、四：同上，每个问题 1~2 句话
  4. 一句话亮点：模型的创新点 / 检验方法（如"通过敏感性分析验证了模型稳健性"）
  5. 结尾：关键词（3~5 个）
- **必须写数字结论**（"最佳时点为 15.25 周""AUC=0.815"），不要只写"建立了模型"
- **必须写模型名字**（"线性混合效应模型""动态规划""逻辑回归"），让评阅人一眼看到你用了什么
- 摘要里**不出现公式、图表、引用编号**

> 摘要写完要反复读：一个完全没看正文的人，能否从摘要知道你做了什么、得出了什么。

---

## 五、模型假设（合理简化，别乱假设）

- 每条假设要**编号**，且**正文里用到的假设要能对上**
- 好的假设 = 简化问题但不过度失真；每个假设后可选加一句"理由/影响"
- 常见假设方向：
  - 忽略次要因素（摩擦、风阻、噪声）
  - 假设分布（正态、泊松、指数）
  - 假设线性/光滑/连续
  - 假设独立/同分布
- **坑**：假设要和模型一致。假设了"正态"后面却用了非参数方法，会被扣分。

---

## 六、符号说明

用表格列出全文符号，格式：**符号 | 含义 | 单位**。所有公式里的符号必须在表里出现。常用符号惯例：
- 决策变量用 `x_i`，参数用 `a, b, c`，时间用 `t`，空间用 `x`
- 概率用 `P`，期望 `E`，方差 `σ²`，相关系数 `ρ` 或 `r`
- 下标统一（`i` 个体，`j` 指标，`k` 组/阶段）

---

## 七、敏感性分析（国赛必考，拉开差距的点）

**几乎每道国赛题都要求敏感性/稳健性分析**，通用做法：

1. **参数扰动法**：把模型里的关键参数（权重、阈值、系数）上下浮动 ±5%/±10%/±20%，看结论是否变化。画一张"参数 vs 结果"曲线或表。
2. **方法对比法**：换一种模型/算法求解，看结论是否一致（如线性回归 vs 岭回归，逻辑回归 vs 随机森林）。
3. **数据扰动法**：去掉部分样本 / 加噪声 / Bootstrap 重采样，看结果稳定性。
4. **结论**：指出"在 XX 范围内结论稳健；当 XX 超过 YY 时结论反转"，这才是有价值的敏感性分析，而不是罗列一堆图。

---

## 八、模型评价（优缺点 + 改进）

- 优点：模型简洁、可解释、契合问题、检验充分、结果稳健
- 缺点：假设的局限、未考虑的复杂因素、数据/参数的不确定性
- 改进方向：如何放宽假设、引入更复杂模型、用更多数据
- **姿态**：客观诚实，评阅人喜欢"知道自己模型边界"的队伍

---

## 九、图表规范（配合 dataviz skill）

- 每张图都要有**编号 + 标题**（图1 xxx，表1 xxx），正文必须引用
- 曲线图：多系列要图例、坐标轴有物理含义和单位
- 热力图/散点：颜色有明确编码含义（分类型用固定色序、大小型用单色渐变、正负型用双色+中性灰）
- 表格：三线表，数值保留合理有效位，标单位
- 出图前调用 `dataviz` skill 检查配色、标记、可读性

## 十、团队分工（3 人）

| 角色 | 职责 |
|---|---|
| 建模手 | 问题分析、模型构建、公式推导、假设与符号 |
| 编程手 | 数据预处理、算法实现、求解、出图、敏感性分析 |
| 写作手 | 论文结构、摘要、图表排版、润色、参考文献 |

**关键**：写作手**从第一天就开始写**（搭框架、填模型思路），不要最后一天才动笔。编程手出结果后立即把结论和图表交给写作手。建模手负责把"为什么用这个模型"讲清楚。

---

## 十一、常见丢分点（避坑清单）

1. 摘要没写数字结论 / 没写模型名
2. 模型假设与模型矛盾
3. 符号说明缺失或与公式对不上
4. 结果只给图不给数值，或数值无单位
5. 敏感性分析缺失或走过场（只画图不分析）
6. 参考文献格式混乱、缺失
7. 堆砌算法却讲不清"为什么用它"
8. 图表无编号、无标题、正文不引用
9. 代码不注释，附录一堆原始输出不加整理
10. 问题之间割裂，没有体现"问题二用问题一结论"的继承关系

---

## 十二、离线自足原则（比赛时可能断网）

比赛期间若无法联网搜题解，按以下顺序推进：
1. 先精读题目，逐问拆解（研究对象/输入/输出/约束/指标）
2. 对照本 skill 家族对应的题型 skill（a/b/c）选方法
3. 用 Python 标准科学栈（numpy/scipy/pandas/sklearn/statsmodels）落地，模板见各题型 skill
4. 结论 + 敏感性分析 + 论文，按本 skill 的八段式成稿

## 十三、模型选择方法论（可辩护的决策链）

> 方法论思路借鉴自 [skillforCUMCM/math-modeling-skill-pro](https://github.com/skillforCUMCM/math-modeling-skill-pro)（专有许可，仅借鉴其**通用建模方法论思路**，本节已用自己的表述重写，未复制其原文/案例/代码）。

模型选择不是"列得越多越好"，而是一条**可审计的决策链**：子问目标 → 数据与数学结构 → 必须满足的条件 → 候选模型 → 反证/验证 → 最简充分模型。

### 1. 先识别输出，再识别算法
不要从"题目出现预测/最优/评价"等关键词直接跳到模型，先写清每个子问的**输入—决策—输出—判据**：
1. 输入是什么（表格/时序/图像/空间/网络/实验/仅机制描述）？
2. 要决定什么（估计参数/预测未来/打分/分组/排资源/设计路径/解释演化）？
3. 输出是什么（数值/区间/排名/标签/簇/策略/路径/曲线/概率分布/建议）？
4. 成功如何判定（误差小/效用大/约束满足/分类对/解释可信/仿真复现/方案稳健）？
5. 输出是否被后续子问消费？若是，必须同时给出**不确定性 + 适用范围**。

**硬规则：模型类别由数学任务决定，关键词只提供弱先验。一句话写不出输出和判据，先不选模型。**

### 2. 六维结构诊断
| 维度 | 诊断问题 | 决定什么 |
|---|---|---|
| 目标 | 描述/推断/预测/评价/控制/优化？ | 主任务类型 |
| 数据 | 样本量、维数、缺失、噪声、标签 | 复杂度上限与验证方式 |
| 关系 | 线性/非线性/单调/阈值/交互 | 函数族与可解释性 |
| 结构 | 时间/空间/网络/层级/序列 | 是否必须保留依赖结构 |
| 决策 | 连续/整数/0-1/路径/顺序 | 优化器与可行性 |
| 不确定性 | 随机/模糊/情景/参数未知 | 区间/鲁棒/随机建模 |

### 3. 三方案设计（A/B/C，三个可辩护层级）
- **方案 A 经典稳妥**：最简充分模型 + 清晰假设 + 标准验证。适用样本小、时间紧、解释优先。禁止把"简单"写成"不做验证"。
- **方案 B 竞赛高分**：保留 A 的可解释骨架，处理题目特有结构/约束，做完整对比与敏感性。进入条件：能指出 A 的具体偏差且改进可验证。禁止只因更复杂就称高分。
- **方案 C 创新探索**：解决 A/B 未处理的关键矛盾（动态权重/分布漂移/随机约束/网络依赖/个体异质性）。进入条件：创新与题意强相关、有消融/基线/理论依据、风险可控。**回退**：增益不稳就退回 B，把 C 当扩展研究。
- 对比维度：预测/拟合、可行性、解释性、稳健性、数据需求、实现难度、计算预算、创新性、展示效果、失败风险。**先满足硬门槛，不要把这些维度强行平均。**

### 4. 硬筛选条件（先硬筛，再软评分）
| 检查 | 淘汰条件 | 修复 |
|---|---|---|
| 数据量 | 参数自由度远超有效样本且无正则/先验 | 降维、简化、交叉验证、贝叶斯先验 |
| 时间可用性 | 训练特征在预测时不可获得 | 重建特征或改任务 |
| 依赖结构 | 随机切分破坏时间/空间/组依赖 | 滚动/分组/空间阻断验证 |
| 可辨识性 | 多组参数产生近乎相同输出 | 固定参数、重参数化、补充观测 |
| 可行性 | 算法不能保证或检查硬约束 | 精确模型、修复算子 |
| 目标一致 | 优化目标与题意/现实价值不符 | 重写目标、多目标结构 |
| 评价语义 | 指标方向/尺度/补偿规则不清 | 数据字典、无量纲化 |
| 可解释需求 | 黑箱无法提供题目要求的机制/建议 | 可解释模型、SHAP 辅助 |
| 计算预算 | 竞赛时间内无法稳定复现 | 降采样、代理模型、启发式+界 |
| 验证能力 | 无真值/无机制/无对照/无稳定性证据 | 重新定义证据或降低结论强度 |

### 5. 何时停止增加复杂度
满足任一即停：外测/交叉验证增益低于实际意义阈值而成本大增；复杂模型只改善训练误差；新增模块无法通过消融证明贡献；复杂度来自模型名而非题目新结构；样本量/标签质量不支持更多自由度；篇幅不足以讲清逻辑链。**最低交付原则：宁可交一个严密验证的经典模型，不交三个讲不清为什么存在的模块。**

## 十四、验证与稳健性方法论（验证从主张开始）

> 方法论思路借鉴自 skillforCUMCM/math-modeling-skill-pro 的「验证从主张开始 / 最低验证包 / 四类不确定性」，已重写。

验证不是论文末尾的固定装饰，而是**对核心主张的反证尝试**。先建立"主张→证据"映射：

| 主张 | 需要的证据 | 不足的证据 |
|---|---|---|
| 预测准确 | 未见数据/滚动外测、合理指标、基线 | 训练拟合优度 |
| 排名可靠 | 权重/标准化/样本扰动下排序稳定 | 一组固定权重的排名 |
| 方案最优 | 可行性、最优性界或精确对照 | 元启发式单次最好值 |
| 方案稳健 | 参数/情景/分布扰动仍可行且效用可接受 | 基准情景表现好 |
| 创新有效 | 公平基线、消融、实际增益、代价 | 模型更复杂或更新 |

### 最低验证包（每个子问至少含）
1. 一个匹配任务的**基线**（预测用朴素/线性，评价用等权，优化用现状/贪心）
2. 一个正确的数据切分 / 小规模精确检查
3. 一个主指标 + 一个互补指标
4. 对关键参数/权重/情景/数据的**敏感性**
5. 一项**误差/失败情景分析**（主动展示至少一个模型失效或结论反转的情景）
6. 有创新模块 → 一项消融；有随机算法 → 多随机种子 + 运行时间
7. 结果进入后续子问 → 不确定性传播或稳定性检查

### 四类不确定性（不得只扰动最容易的参数）
数据不确定性（测量误差/缺失/采样偏差）、参数不确定性（估计误差/专家区间）、结构不确定性（候选模型不同）、情景不确定性（未来政策/需求/环境不可概率化）。

### 公平对比与消融
所有模型用同一训练信息、切分、指标、调参预算（预算不同要明说）；消融逐一删除新特征/约束/模块证明贡献；多折/多种子报分布不只报最优；`p<0.05` 不等于实际重要，同时报效应量与置信区间。

## 十五、子问题依赖图与误差传播

> 方法论思路借鉴自 skillforCUMCM/math-modeling-skill-pro 的「问题依赖图」，已重写。

好的拆解不是按"问题一二三"机械分段，而是形成**可执行的有向图**：节点是可独立定义输入/输出/判据的任务，边表示数据/参数/状态/决策/证据依赖。

### 依赖边类型
| 边 | 含义 | 必须携带 |
|---|---|---|
| 数据依赖 | 下游用清洗/特征后的数据 | 字段、单位、切分、缺失规则 |
| 参数依赖 | 下游用上游估计的参数 | 估计值、区间、相关性 |
| 预测依赖 | 下游以未来量做决策 | 分布/区间/情景，不只点值 |
| 评价依赖 | 排名/得分影响资源分配 | 权重、尺度、排名稳定性 |
| 决策依赖 | 前一决策改变后一系统 | 决策变量、可行性、成本 |
| 证据依赖 | 后续验证需前一基线 | 相同切分、指标、预算 |

### 典型结构
- **串联**：数据→估计→预测/评价→优化→建议（风险：上游误差级联，需端到端情景）
- **分支**：共同底座→多个独立子问（共享数据字典，不要人为串起来）
- **汇合**：需求预测+风险评价+成本估计→多目标/鲁棒优化（查量纲、口径、重复信息）
- **迭代/反馈**：状态估计↔决策（写明初值、收敛、最大轮数、无收敛回退）
- **分层**：宏观约束→微观分配（验证上层方案在下层可实施）
- **情景扇出**：共同模型→多未来情景（情景来自历史/区间/政策边界，不是随意三组数）

### 误差传播
上游输出 `z=g(y,θ)` 而 `y` 是上游估计时，至少选一种传播：Delta method / Bootstrap 重跑整条链 / Monte Carlo 从上游联合分布采样 / 分位数·场景集 / 区间·鲁棒集合。**下游对上游误差不敏感也要用结果说明，而不是省略检查。** 上游结果进优化/评价时保留样本/分位数/情景，不只传均值。

## 十六、创新点与证据阶梯

> 方法论思路借鉴自 skillforCUMCM/math-modeling-skill-pro 的「创新点生成与证据框架」，已重写。

竞赛创新是对题目关键矛盾的**有证据改进**，不是复杂模型的同义词。一个创新点需同时含：**原方案缺陷 + 面向题目的改动 + 可测影响 + 适用边界**。

### 从缺陷找创新（不是先找热门算法）
信息损失（把时间/空间/异质性压成均值）→ 假设失配（线性/独立/平稳不成立）→ 现实缺口（容量/公平/成本/政策）→ 评价缺口（只看平均误差）→ 计算瓶颈（昂贵仿真/大规模组合）→ 表达缺口（难解释/缺不确定性）。

### 六类可迁移创新
模型结构（时变/分段/层级/网络）、模型组合（预测→优化、机理→残差）、指标/目标（公平/风险/尾部）、约束与决策（容量/时间窗/鲁棒，常比换求解器更提现实性）、数据与特征（机制特征/聚合，禁未来信息）、算法与求解（专用邻域/分解/热启动，禁只换 GA/PSO 名称）。

### 证据阶梯（结论强度不得超过证据等级）
弱→强：①逻辑合理 ②个别案例改善 ③固定验证集改善 ④消融证明贡献 ⑤多种子/多切分/统计显著 ⑥分布漂移下仍稳 + 机制解释。

### 伪创新否决条件
仅换更深网络/更新算法名；无基线；用未来数据/测试集挑最优；新指标与旧指标高度重复；组合无法说明接口与误差传播；为结论漂亮删不利情景；只报训练拟合或单次元启发式；把常规预处理/调参包装成创新；微小改进却称"显著提升"。

## 十七、冲击一等奖：优秀论文的核心打法

> 提炼自 2021–2025 年 64 篇获奖论文语料统计、5915 页优秀论文分析、国赛官方评阅标准与一等奖队伍经验分享。

### 1. 评阅四原则与权重（把精力花在刀刃上）
评审四原则：**假设的合理性(20%)、建模的创造性(25%)、结果的正确性、表述的清晰性(25%)、格式规范(15%)、参考文献(15%)**。国一 = 90–100 分：五项均优秀 + 模型有明显创新 + 论文表现突出。
- 启示：**创造性 + 清晰性占半壁江山**，别把时间全耗在堆算法上；结果正确性是底线（编造数据 / 结果严重偏离 = 直接出局）。
- 申报国一的论文实际约 1/3 能评上，约 5% 申报一等奖最终不获奖——**稳比炫重要**。

### 2. 核心心法：高分论文都在做"证据链"
读完 5915 页优秀论文的结论：高分论文最稳定的共同点**不是"模型多"，而是把「题目 → 小问 → 模型 → 数值结果 → 验证」组织成一条可复核的证据链**。评阅人顺着这条链能一步步复核你的每一步。
- 每个子问都要能自问自答：用什么模型 → 为什么用它 → 结果是多少 → 怎么验证这个结果是对的。

### 3. "超额创新"是国一与国二的分水岭
国一与国二的核心区别在**超额创新**：自创算法、跨领域模型融合、对经典方法的突破性改进。但铁律是**"标新立异，但要合理"**——创新必须有可验证的增益（消融 / 基线 / 理论依据），否则被判伪创新。
- 正确姿势：不是"用了 LSTM+灰色模型"就叫创新，而是"指出经典模型在本题哪一步失配，再针对性改动并证明有效"。

### 4. 候选模型对比：≥2–3 个"结构性不同"的模型 + 选型理由
别只给一个模型。至少给 2–3 个**结构性不同**的候选模型（如逻辑回归 vs 随机森林 vs SVM，而不是 BP/RBF/LSTM 这种同族假对比），并给出选型理由（适配性 + 数据规模 + 求解时间 + 文献支持）。
- 典型扣分反例："BP 应用广泛，故选用"——选型理由薄弱。

### 5. 模型检验是三等到一等的关键差距
灵敏度 / 误差 / 鲁棒性检验要**嵌入每个子问题求解末尾**（每子问题 0.5–1 页），不是只在最后独立成章走过场。
- 必做：灵敏度(±10%/±20%)、误差(MSE/MAE/R²)、候选模型对比。
- 加分：Monte Carlo 鲁棒性、关键假设回验、交叉验证。

### 6. 摘要量化标准（权重 30%+，30 秒判奖项）
- 篇幅 **600–1400 字**（获奖常见约 1000–1400 字符），"1+N"结构：总述 + 每问一段 + 末段评价。
- 每问必备三件套：**方法 + 求解思路 + 关键数值结果**；禁用"较优/较好/显著提升"等空洞词，**必须给数字**。
- 铁律：不出现公式 / 符号 / 表格；摘要与正文严格一致（摘要写 LSTM、正文却用 BP 是重灾扣分）。
- 参考文献 ≥8 篇（方法创新型可少但要有理由），能引英文期刊论文更佳。
