# Rule-Pack Consumer: Model Selection

At the repository root, load `07_modeling_pattern_cards.yaml` from the canonical rule pack. Query cards by problem type and trigger conditions, then record: candidate models, rejected alternatives, assumptions, required validation, and recommended figures. Write `dependency_analysis.json` with `shared_kernel_required`; only true permits a unified-model section.

Inputs: parsed problem and structured requirements. Outputs: dependency analysis, candidate comparison, selected model plan. Failure: missing comparison, absent validation plan, or a pattern copied as a task-specific answer blocks selection.
