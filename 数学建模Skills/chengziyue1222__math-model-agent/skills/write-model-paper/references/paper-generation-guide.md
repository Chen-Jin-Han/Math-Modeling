# 竞赛论文生成指南

本文档定义生成行为；可验证性检查仍在后台，但不把工程对象、运行状态或机器标识写进竞赛论文。

## 摘要

摘要第一页完成。第一段交代问题本质和整体框架；随后按题号用紧凑段落交代“方法—核心求解—关键结果—必要验证”；最后可用一句话交代适用价值或边界。只保留能改变读者判断的数值，关键词取 4--7 个。结果无证据、过长背景、口号式创新和正文未展开的结论均不写。

## 结构与分层

默认顺序是：摘要、关键词、问题重述、问题分析、模型假设、符号说明、（条件性）统一模型层、各问题的模型建立/求解/结果与分析、模型检验与灵敏度分析、模型评价与推广、参考文献、附录。国赛论文不设置目录。

仅当依赖分析确认至少两题共享状态、约束、数据、几何、目标或求解内核时，才写统一模型层。摘要为电子版第 1 页，问题重述在摘要之后直接开始，页码从摘要的 1 连续递增且正文不得重置。参考文献和附录另起页。附录前的全部论文内容不得超过 30 页。一级标题居中，二三级标题左对齐，不使用左上角运行标题。

## 写作单元

- 问题分析回答为何采用该路线：对象、难点、依赖、判据和输入输出，不重复题目。
- 模型建立按“现实关系 → 数学表达 → 公式 → 参数/单位解释”展开。公式前说明目的，公式后定义符号、计算方法和适用范围。
- 结果分析按“结果 → 规律 → 原因 → 证据 → 实际含义”展开。图前说明要验证的结论，图/表后只解释最关键的比较。
- 限制说明必须写受影响结论、可能偏差方向或补救实验中的至少两项。

避免套话（如“值得注意的是”“从图中可以看出”“进一步地”“综上所述”）以及“rule_id、registry、state machine、verified JSON、delivery contract”等工程术语。

## 图表、引用与附录

图由结论选择，表默认三线表、表题在上、单位写在列名/表注，正文只保留代表结果；全量数据放支撑材料。模型、经典算法、业务事实或非原创定理才引用，不能核验则不引用；参考文献独立起页。附录必须给出支撑材料的完整文件清单，并按模块包含全部自有、完整、可运行源程序。第三方库只列名称、版本、依赖文件和可安装说明，不嵌入其完整源码或二进制。PDF 中代码不得以不可读小字号压缩。

支撑材料必须从清单生成 ZIP/RAR，逐项核对清单与归档内容，并在干净临时目录解压后执行声明的复现命令。所有本地 import、数据、配置、字体和绘图资源都必须随包提供；缺少任一项或命令非零退出即失败。competition 默认交付 PDF，PDF/DOCX 二选一；audit 同时交付两种格式。论文文件和支撑材料压缩包分别不得超过 20 MiB。
