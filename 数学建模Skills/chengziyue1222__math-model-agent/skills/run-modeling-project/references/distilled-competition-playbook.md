# 竞赛建模蒸馏工作法

本工作法保留分阶段资料中可复用的推理结构，同时把经验建议与硬性规则分开。赛事规则以当届官方文件为准；本文件只规定工作方法。

## 一、先建立任务卡

开始计算前，为每个子问题写清：

- 输入数据、对象、时间与空间范围、单位；
- 决策变量或待估参数、目标、硬约束与软偏好；
- 需要交付的数值、排序、策略、图表或解释；
- 与其他子问题共享的状态、数据、约束和求解内核；
- 不确定信息、需要查证的外部事实和可能改变路线的条件。

把题目拆成 `输入 → 关系/机制 → 输出 → 验证`，但不要为了形式强行统一所有子问题。

## 二、使用“主路线 + 基线 + 反证”

每个关键结论至少对应：

1. 一个由题意和数据支持的主路线；
2. 一个足够简单、可解释的基线；
3. 一个能暴露失败的检验，例如时间外推、极端情形、约束审计、替代算法或独立重算。

先问“什么证据会推翻这条路线”，再决定模型复杂度。无法识别的参数、缺少支持的数据范围和未经验证的单调性都必须触发降级或改模。

## 三、阶段交付必须可回滚

阶段交付应包含决定、证据、未决风险和下游依赖。后续发现矛盾时，不得以“前一阶段已经确定”为由继续堆叠；应记录变更原因，回到最早受影响的阶段，并重生成其下游结果、图表和文字。

## 四、结果叙述使用五联句

对每个重要结果依次说明：结果、模式、机制、证据和含义。结果应给出可核对的数值、区间、排序或可行方案；证据应来自基线、误差、约束、敏感性或独立复核；含义必须回答原题并说明适用边界。

## 五、图表服务于论证

图表数量由证据链决定，不设配额。每张正式图必须有明确主张、机器可读源数据、单位、必要的基线或阈值，以及正文中的解释。编辑已有图时保持数据和语义不变；若改变图型、尺度或聚合方式，记录理由并重新核对结论。

## 六、答辩材料仅在用户需要时生成

答辩页不复制论文，而围绕三个问题组织：问题为何值得研究、方法为何适配、结论为何站得住。每页只承担一个中心主张，并给出能支撑它的图、表或公式。赛前按真实时限排练，优先准备对数据来源、模型选择、稳健性和局限的追问；未知问题应说明边界和补充验证方案，不得虚构答案。

## 七、明确拒绝的捷径

- 不以公式、图表、模型、创新点或参考文献的固定数量代替质量。
- 不采用通用的“误差小于某百分比即优秀”阈值；阈值必须来自任务损失、领域容差、基线或不确定性。
- 不反复查看测试集并调参直到“通过”；测试集或最终外推段只能用于预先约定的最终评估。
- 不把合成数据、推测参数、伪造下载链接或无法核验的文献伪装成真实证据。
- 不根据文字风格猜测是否使用 AI；AI 使用情况只能由实际交互记录、生成文件、版本历史和人工核验记录确认。
- 不预测奖项或用内部评分冒充评审结果。
