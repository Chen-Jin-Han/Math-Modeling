# 数学建模图型路由与多面板设计

## 先按信息任务选图

| 读者需要回答的问题 | 优先图形 | 必须交代 | 常见误用 |
|---|---|---|---|
| 数据随时间怎样变化 | 折线、阶梯图、事件时间线、置信带 | 时间顺序、缺测、预测起点、区间含义 | 用类别柱图破坏时间连续性 |
| 两组或多组是否不同 | 原始点 + 箱线/小提琴/点区间 | `n`、中心统计量、离散或区间定义 | 小样本只画均值柱 |
| 两变量是否相关 | 散点 + 趋势/区间；必要时边际分布 | 相关类型、拟合范围、异常点处理 | 用平滑线暗示未经验证的因果 |
| 多变量结构是什么 | 相关热图、PCA/降维、聚类图 | 标准化、距离、解释方差、组别 | 每个单元格都加粗标数 |
| 模型预测是否可靠 | 观测-预测、残差、校准、ROC/PR、误差分布 | 数据切分、基线、指标、区间、随机种子 | 只展示训练集拟合 |
| 多模型谁更好 | 排序点区间、临界差异图、泰勒图、成对比较 | 统一测试集、指标方向、折数/种子 | 雷达图掩盖细小差异 |
| 参数怎样影响结果 | 单参数响应、龙卷风、二维响应面、可行域 | 基准点、参数范围、阈值、约束 | 无实际含义的 3-D 透视 |
| 优化算法是否可信 | 收敛曲线、最优值分布、约束余量、独立复核 | 停止准则、运行次数、可行性 | 只画一次最好轨迹 |
| 方案在情景下是否稳健 | 情景带、压力测试、风险-收益前沿、概率图 | 情景定义、决策阈值、不确定性来源 | 把情景差异说成统计显著 |
| 空间或网络结构是什么 | 地图、流向/网络、邻接热图 | 坐标系、尺度、方向、节点/边含义 | 线交叉过多或面积编码不实 |
| 模型机制或解题流程是什么 | 变量关系示意、技术路线图 | 输入、共用内核、分支、验证、输出 | 把完整公式塞进流程图 |

饼图、雷达图、桑基图、和弦图和三维图只在其编码确实优于更精确的二维替代时使用，并说明选择理由。

## 数据形态约束

- 类别过多时优先排序、分面、合并有依据的长尾或直接标注，不要无限扩展颜色。
- 点数过多时使用透明度、栅格化数据层、hexbin 或密度表达，不随机抽点伪装全量数据。
- 对数坐标要求正值；负数、零值和移位处理必须显式说明。
- 发散色标只有在零、基准值或政策阈值是有意义的中点时使用，并固定 `vmin`、`vcenter`、`vmax`。
- 跨面板比较同一变量时共享轴域或色域；若不能共享，明确标注差异。

## 多面板设计简报

两幅及以上面板先写五行：

```text
画布：单栏/双栏 · 4:3/3:2/宽幅/纵向 · 最终宽度
核心信息：读者三秒内应得到的结论
布局配方：evidence-grid / hero-plus-proof / workflow-to-result / landscape-comparison
英雄面板：面板、证据及其为何占主导；等权网格可写“无”
支持顺序：每个面板新增的非重复证据
颜色角色：基线、比较、强调、背景各对应什么对象
```

### 布局配方

- `evidence-grid`：2×2 等权证据，适合尺度一致的比较、诊断、稳健性和验证。
- `hero-plus-proof`：主地图、热图、轨迹或关键结果占支持面板的约 1.2–1.5 倍面积。
- `workflow-to-result`：紧凑流程/机制图加 2–3 个结果面板；若流程不是理解数据的前提，结果先出现。
- `landscape-comparison`：共享基线的横向基准、消融、时间或情景序列，优先在曲线末端直接标注。

## 去冗余检查

逐对检查面板：是否使用同一数据回答同一问题、是否可由另一面板直接推导、遮住它是否不损害结论。任一为“是”时，合并、改成正交证据或删除。优先采用“总体模式 → 偏离/机制 → 稳健性/验证”的证据递进。

面板阅读顺序通常为左到右、上到下。相同尺度的面板相邻；发现先于验证；简单证据先于需要学习新视觉语法的密集图。
