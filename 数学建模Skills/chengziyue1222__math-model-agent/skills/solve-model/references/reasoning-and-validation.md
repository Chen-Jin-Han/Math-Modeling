# 求解与论证

求解的目标是获得能在论文中解释的结果，而不是只得到一个求解器状态。

1. 先把现实关系写成变量、单位、目标、约束和适用范围；公式前说“为什么需要它”，公式后定义符号并说明如何计算。
2. 有解析结构时，先推导可行域、守恒、单调性、初值或缩放关系，再把数值法限制在真正无闭式的部分。
3. 对临界事件，保存事件函数、首个候选括号、精化结果和左右状态；把算法容差、物理阈值、扫描步长、展示精度分开。
4. 对搜索，先验证单调性或可行集结构；无法验证时不可把二分结果称为全局解。
5. 每个关键结论至少选取适合它的证据：约束审计、简单基线、独立算法、极端情形、灵敏度或步长收敛。不要用“残差很小”代替模型可信性。
6. 写作时将内部的 PASS/FAIL、哈希和运行日志翻译为可读论证，例如“步长减半后关键指标变化小于 …”，而不把后台术语写入正文。

将验证分为三类并避免混淆：

- **正确性**：单位、边界、守恒、约束和独立重算；
- **数值稳定性**：容差、步长、迭代与收敛；
- **结论稳健性**：参数、场景、权重或样本改变后结论是否跨越决策阈值。

验证方案必须由结论类型决定：预测使用时间顺序或分组留出与朴素基线；优化使用可行性、上下界、对偶或替代求解器、多起点；仿真使用多随机种子、置信区间和守恒检查；机理模型使用量纲、边界、极限情形与参数可识别性；排序或评价使用权重、归一化和删指标敏感性。

不要设置跨问题通用的优秀阈值，也不要“验证直到通过”。在查看最终留出结果前固定主要指标、容差和决策规则；若失败，应报告失败、诊断原因并回到模型选择或数据阶段。任何改模后的最终性能都需要新的未污染评估或明确标注为探索性结果。
