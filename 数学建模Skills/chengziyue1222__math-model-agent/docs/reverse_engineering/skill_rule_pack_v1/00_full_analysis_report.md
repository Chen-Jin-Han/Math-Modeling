# 数学建模 Agent 样稿逆向与 Skill 工程化分析报告

## 执行摘要

两份目标样稿的核心价值不在某道板凳龙题目的具体公式，而在四条可迁移能力链：

1. **统一建模内核**：先找子问题共同状态、接口和判据，再由各问调用；文件 A 的“路径层—链层—速度层—碰撞层”比逐问重复建模更利于一致性和验证。
2. **代码先行的证据闭环**：解析/数值求解、实体判据、首次事件、嵌套优化、上包络峰值均由真实代码执行，并配约束审计、交叉验证和敏感性。
3. **论文的证据型版式**：题目+摘要、目录、问题重述、分析、假设、符号、基础模型、逐问结果、验证、评价、参考和附录；图形不是装饰，而承担构型、事件、收敛和可行域证据。
4. **必须反向修复的缺陷**：文件 B 存在明显数字矛盾；两份样稿的参考文献与附录未真正单独起页；代码字号过小；多个流程图缩放后不可读；高精度残差有被包装成模型正确性的风险。

当前资料包中的主 Skill 仅负责科学图生成，不能承载完整数学建模论文工作流。推荐新建总控/写作/验证/排版 Skill，并将现有图形 Skill 作为子工具调用。当前 `main_v2.pdf` 应作为格式回归夹具：保留计算结果，只调整摘要、目录、版心、图表、验证章节和附录策略。

## 2. 页面格式取证

- 三份均为 A4 纵向。A/B 的正文长行从 x≈70.87 pt 到 524.41 pt，约等于左右 25 mm；C 约为 89.86-505.41 pt，即左右 31.7 mm。
- A/B 的正文中文为 SimSun，西文为 Times New Roman，主字号 12.005 pt；一级标题 15 pt SimHei 居中，题目 16 pt，摘要标题 14 pt。
- A/B 的常规正文基线步长约 19.87 pt；C 为 21.67 pt，导致同样字号下每页信息密度更低。
- 表格主要为三线表；图题在图下，表题在表上。图表前后通常有引出和分析，这是值得迁移的写作节奏。
- A/B 的参考文献和附录标题位于页面中段，说明没有真正 `clearpage`；用户要求的“单起一页”应作为反向修正规则。
- A/B 的代码附录采用浅灰背景和语法着色，但字号 5.5/6.5 pt，不适合最终阅读；应精简正文附录并把全量代码放提交包。

## 3. 摘要与正文结构逆向

A/B 摘要均约 1200 字，并遵循“统一内核—逐问方法与关键数值—验证—关键词”。可迁移的是结构，不是十余位小数。新 Skill 应把摘要放在最后生成，并从 claim registry 读取关键量。

正文应采用条件式结构：

- 有共用内核：问题重述→问题分析/依赖图→假设→符号→统一模型→各问调用→统一验证。
- 无共用内核：问题重述→问题分析→假设/符号→逐问模型与结果→统一验证。

每问的基本单元是“模型建立—求解流程—结果与分析”。结果段必须同时回答数值是什么、为何如此、是否可信和适用边界。

## 4. 图、表、公式和附录

样稿有效的图形语法包括总体路线、几何示意、多时刻快照、全局+局部临界图、时间曲线、热图、可行域、响应面和收敛曲线。迁移时必须引入图注册表，记录 claim、源数据哈希和证据角色，防止重复图和手工改数。

表格使用三线表、单位列、统一小数位。全量逐时刻结果进入 XLSX/CSV；正文只保留代表对象。公式前说明目的，公式后解释变量和计算方式。附录只放关键代码和复现说明，完整源码进入提交包。

## 5. 建模方法模式库

本规则包抽象了 15 个可迁移模式：共用内核、一维参数化、闭式+反解、链式约束、解析导数传播、实体几何、带符号事件函数、嵌套优化、单调性验证、对称性降维、线性齐次、上包络峰值、硬约束审计、独立交叉验证、敏感性与收敛性分离。每个模式都包含触发条件、输入输出、失败模式和强制验证，详见 `07_modeling_pattern_cards.yaml`。

## 6. Agent 工作流逆向

从目录、模块化代码、结果文件和验证章节看，两份作品更像“规划/建模—编码执行—验证—绘图—写作—LaTeX 编译”的多阶段模板驱动流程，而非一次性大模型直出。无法仅凭 PDF 证明具体 Agent 数量或是否人工修订，因此所有工作流判断仅为高可信推断。

真正需要工具执行的阶段：数据读取、代码运行、求解器调用、文献核验、图表生成、数字一致性、PDF 预检和干净环境复跑。大模型可以生成候选模型、解释草稿和章节初稿，但不得自证计算或引用真实。

## 7. 错误和风险审计

最严重问题来自文件 B：

- pp.6、21 的最小螺距出现多个不同值和不同终区间；
- p.20 的表格与紧邻文字给出不同坐标和速度；
- p.6 声称最小间隙单调收紧，而 p.18 明确展示振荡下探。

这说明最终 Skill 必须使用 canonical result + quantity_id，而不能允许写作模型手工复制数字。A/B 共同风险还包括附录代码过小、流程图文字过密、高精度数字泛滥、求解器残差被过度解释以及“独立验证”可能共享关键判据。

## 8. 两篇作品优劣

- 文件 A：结构、统一接口、数值风险意识、验证和敏感性更强；缺点是冗长、代码附录比例过高、摘要过密、过度精确和图内文字偏小。
- 文件 B：正文更紧凑、逐问结构直观、图形数量足；缺点是多处严重数字矛盾、论证跳跃、单调性表述冲突和附录编号错误。
- 推荐融合：采用 A 的统一内核与验证，采用 B 的篇幅控制和逐问可读性，同时强制 canonical result、独立验证依赖审计和 PDF 可读性门。

## 9. 最佳实践融合

无强制页数限制时，正文建议 28-42 页；摘要一页，目录 2-3 页，参考文献单独起页，附录精简到能复现关键逻辑。每个核心问题至少有一张“结构/过程”图和一张“结果/验证”图，但总图数由证据链决定，不设装饰性配额。

## 10. Skill 模块架构与改造路线

P0 先做真实执行、claim registry、硬约束、数字一致性、参考核验、失败阻断和 PDF 预检；P1 再做模板、图表和分页；P2 做 schema、清洁环境和自动报告；P3 才做语言与视觉微调。

详细目录、接口和验收规则分别见 `09_agent_workflow.yaml`、`10_skill_integration_requirements.md` 和 `12_acceptance_tests.yaml`。

## 11. 尚无法确定的事项

1. 资料包未包含目标数学建模仓库的全量当前源码，只包含一个图形 Skill、目录资料、当前 PDF 和审查报告。
2. 没有 `main_v2.pdf` 的 LaTeX 源、数据和 canonical result，暂不能直接修改模板并验证数值不变。
3. 没有赛事最新强制模板和页数规则；所有版式默认值必须允许赛事配置覆盖。
4. 样稿附录代码能否真实复现全部数值，需要独立运行源文件才能确认，PDF 代码文本本身不足以证明。
5. 文献真实性需要联网逐条核验，本轮只建立核验门，不把样稿文献自动纳入通用库。
