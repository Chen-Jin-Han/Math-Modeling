# 删除、合并、冻结建议

本文件是后续变更决策，不是删除授权。本次审计没有删除、移动或重写任何仓库文件。

## 立即冻结/隐藏

| 对象 | 建议 | 理由 | 前置条件 |
|---|---|---|---|
| `legacy/skills/` 的 56 旧命令 | 冻结为兼容归档；从参赛 README、UI 和视频隐藏 | 已被 `validate_legacy_archive.py` 定义为 compatibility-only；会稀释 8 标准 Skills 主线 | 保留 command-map 与验证器 |
| 129 全量 API 的直接展示 | 参赛界面隐藏，保留 Python 库 | 算法数量不是教育智能体价值；会造成“算法仓库/命令集合”印象 | 建立小型 curated adapter |
| 一键论文/最终解答叙事 | 停止宣传 | 教育诚信和竞赛代做风险 | 改为比较、验证、审阅与确认 |

## 合并建议

1. 不合并算法源文件。17 模块有明确领域职责，当前测试和导入路径依赖它们；未做重复度量和逐模块来源核验前合并风险高。
2. 合并参赛产品层的能力：把三个独立示例在新场景编排层中串为一个任务图，而不是复制 `solve.py`。共享合同应含数据来源、单位、参数、seed、基线、失败记录和 Manifest。
3. 以 adapter 统一参赛核心结果对象，不要求一次性修改 129 个旧 API。优先覆盖预测、线性规划、M/M/s/K 和模型评价。

## 删除建议（条件式）

- `examples/**/__pycache__/`、临时 SVG/JSON 仅在它们可由命令稳定重建、且运行 Manifest 已记录时才从版本控制候选中排除；目前 `examples/` 未跟踪，先不要删除任何现有产物。
- 对来源不清、无测试、无教学用途的算法或模板，待完成 `THIRD_PARTY_NOTICES.md` 和 usage 盘点后再决定删除；本次未发现足够证据支持直接删除某一算法文件。
- `.legacy-final-temp/` 本次无法读取（权限拒绝），不对其中内容作删除判断。应由仓库所有者在确认路径和可恢复性后处理。

## 129 API 收缩方案

| 层 | 对外数量建议 | 内容 |
|---|---:|---|
| `algorithms` 原库 | 129（兼容保留） | 不破坏现有用户 |
| `modeltrace.core`（新） | 8--12 | `forecast`、`allocate`、`queue_risk`、`evaluate`、`validate`、`manifest` 等有统一 Result/seed/错误语义的任务级能力 |
| 学生界面 | 3--5 个动作 | 审计数据、比较模型、运行受控任务、确认、导出证据 |
| 教师界面 | 3--5 个动作 | 审阅证据、退回、确认、导出匿名评价 |

## 维护边界

应继续维护：`scripts/run_manifest.py`、`project_state.py`、五个高覆盖关键算法、三例旗舰场景和合规检查。应停止把 legacy 文档、图表模板和全量算法清单作为参赛核心展示。任何删除/合并均应在独立提交、干净环境复跑和许可证核验后进行。
