# 推荐产品方案

## 产品定义

- 名称：**模证通（ModelTrace）——可审计的人机协同数学建模教学与过程评价智能体**
- 申报赛道：教育智能体（可扩展为教育 + 科研辅助）。
- 一句话主张：**不替学生代做建模竞赛；让每一次模型选择、求解、验证和人工确认都可追溯、可复现、可教学。**
- 目标用户：学习数学建模的大学生、课程/竞赛指导教师、校园实践项目组织者。
- 核心痛点：学生会调用算法却难以解释模型为何适用、结果是否可信；教师难以在短时间内查看数据、假设、基线、失败尝试和复现证据。

## 旗舰场景：校园大型活动资源决策实验

以“校园开放日/大型活动”为单一连续案例：学生先用合成或获授权历史数据预测参与量，再做物资/志愿者调度，最后评估入口排队风险。当前仓库的 `examples/demand_forecasting`、`supplier_allocation`、`queue_risk` 可以作为**可复用算法演示资产**，不是已完成的一体化产品。

学生流程：提交数据与问题描述 → 数据/单位/缺失项检查 → 比较候选模型和基线 → 运行求解与敏感性分析 → 查看失败候选和限制 → 明确确认后导出可复现报告。

教师流程：查看任务分解、数据来源、模型选择理由、seed/环境/产物哈希和学生确认记录 → 针对证据提出反馈 → 审阅或退回阶段门 → 导出匿名化教学评价摘要。

## 智能体架构（现有与待补齐）

```text
问题与数据
  -> 数据审计/追问（P0 新增界面与规则）
  -> 候选模型路由（现有 select-model Skill + curated API）
  -> 求解与基线（现有 algorithms）
  -> 验证/敏感性/失败记录（现有部分测试、Manifest；P0 补场景规则）
  -> 人工确认（P0 新增）
  -> 证据链与教师审阅（现有 Manifest/state 基础 + P0 新增）
```

现有的自主性证据：`project_state.py` 强制相邻阶段推进、证据哈希、block/resume；`run_manifest.py` 记录文件哈希、参数、环境、失败和限制。待实现后才能宣称的自主性：根据数据质量拒绝模型、动态选择工具、向学生追问、教师审批、可视化状态和反馈闭环。

## 人机与合规边界

1. 系统可以建议模型、执行受控算法、展示基线和检验结果；不能把未经确认的结果表述为最终竞赛答案。
2. 每次随机运行必须显示 seed；每个结论显示数据、代码、指标和限制的链接。
3. 教师端只审阅匿名化项目标识；正式参评材料不得包含姓名、学校、学号、邮箱、绝对路径或 Git 作者信息。
4. 合成数据必须显著标记；真实数据必须有来源、许可、脱敏和使用范围。
5. AI 生成的解释、图表建议和文本必须标记为 AI 辅助并经学生/教师确认。

## 与通用大模型的差异

不是“问一句就给答案”。它把大模型建议限制在可验证的工作流里：结构化数据契约、算法执行、基线对照、失败候选、哈希 Manifest、阶段门和教师审阅。没有这些证据时，系统应显示“未验证”，而不是生成确定性结论。

## 五项评分策略

| 评分项 | 现有证据 | P0/P1 补强 |
|---|---|---|
| 需求与场景 25 | 三个可运行决策子问题；教育/诚信边界清楚 | 访谈至少 3 名学生/1 名教师并记录真实需求 |
| 创新与实用 25 | 证据链、失败记录、阶段门结合算法库 | 展示“拒绝不合格候选 + 教师退回”而非炫算法数量 |
| 技术完整 20 | 244 测试、Ruff、覆盖率、Manifest、state | 一键 demo、双角色入口、完整错误处理 |
| 数据与算法 15 | NetworkX/SciPy 差分测试、seed、M/M/s/K、LP | 公平基线、敏感性、真实/授权数据合同、模型卡 |
| 体验与展示 15 | 三例有 JSON/SVG；尚无 UI | 任务图、候选模型、运行状态、证据链、人工确认可视化 |
