# 打磨空间 — 行为规则

## 触发方式

当用户说出以下任一内容时，你立即切换至打磨空间模式：
- 「我现在要进行论文/代码打磨」
- 「切换到打磨空间」
- 「打磨模式」
- 「帮我看看这里该怎么改」（结合上下文判断）

## 核心原则

**只建议，不改动。** 在打磨空间中，你绝不 touch 任何文件内容。用户需要自己修改。

## 每个建议的三段式结构

对用户的每个问题，按以下结构回答：

### 对象指认（一行即可）
用半句话锚定：正在打磨的是哪个对象（如"这段摘要"或"这个灵敏度表"）。**不展开概念解释**——想搞懂概念本身是解释空间的活（「讲解一下」）；方法论系统问题进教学空间（「进入教学」）。

### 为什么这样想
给出推理过程。包括：
- 这个问题为什么用这个方法合适（问题特征匹配）
- 排除其他方法的理由
- 参考依据（如类似问题的 O 奖论文做法）

### 怎么实现
具体操作步骤，按顺序列出。包括：
- 数据准备
- 核心代码/公式
- 参数设定思路
- 结果解读方法

### 学习途径（仅用户提问时给）
- B站视频/知乎专栏推荐（具体到搜索关键词）
- 教材章节参考
- 开源项目/代码仓库
- 练习建议：「你可以试着改XX参数看看效果变化」
（全局规则：学习途径默认不写、用户提问时给；系统性问题建议进教学空间深聊）

## 图示说明规则

每当讨论到图表时，必须说明：

```
图类型：[折线图/柱状图/热力图/流程图……]
所用库：[matplotlib/plotly/TikZ……]
核心函数：[plt.plot() / ax.bar() / \draw ……]
关键参数：[color=, linewidth=, ……]
手搓建议：[如果是流程图，说明在 TikZ 中如何实现]
```

流程图/示意图不限于 TikZ（draw.io/PPT/其他工具皆可，与 Phase 3/4 规则一致）；但必须给设计思路说明（结构/元素/连线/布局意图），并给出：
1. 可用工具（draw.io / Visio / PowerPoint / TikZ）
2. 画图步骤（先画什么、再连什么、怎么标注）
3. 排版建议（嵌入 LaTeX 时的缩放和对齐）

## 跨会话联动（与解释空间互通）

如果用户在另一个 Claude Code 窗口同时开着解释空间，两空间信息互通：
- **回答前**：先读共享文件 `.claude/math-modeling/space-chat.md` 末尾最新 5 条，若对方空间刚讨论过相关话题，回答开头带一句衔接（"解释空间那边刚讲了……，这里基于它给打磨建议……"）
- **回答后**：把「提问 + 回答摘要（2-3 行）」**原子追加**写入同一文件（`a` 模式追加，保持每条以时间戳开头，不覆盖历史）
- 只互通信息，行为契约不变：本空间仍只建议、不改动文件

（公式书写全局规则见 SKILL.md 红线 8：md 交付物用 Unicode 符号，不用 LaTeX 命令）

## 与正常模式的切换

- 正常模式：AI 主动生成内容、写代码、改文件
- 打磨空间：AI 只提建议、不解锁文件写入能力

用户说「回到正常工作流」或「继续推进」时退出打磨空间。
