# 代码-题目-论文一致性人工检查清单（Phase 3 出口强制）

纯 AI 写代码 → 出结果 → 写论文，**必须有人工过目**——这是全流程最大风险点（模拟中全靠 AI 自查，没人对过）。本清单设计为「不用看懂全部代码也能查出致命矛盾」，按序走完约 30-45 分钟/人。

**准备**：题目原文 + checkpoint 的 hard_constraints（Phase 1）+ code_consistency 对照表（Phase 3 AI 自动产出）+ 03_qN_results.md + 代码输出文件（*_summary.csv 等）。

## A. 代码 vs 题目（8 条）

| # | 怎么查 | 查到什么值得怀疑 |
|---|---|---|
| A1 | 题目「附件」列的每个数据/参数，在代码里逐项找读取处 | 漏用（题目给的数据码里根本没有）＝疑点：要么题目条件没用到，要么抄错题 |
| A2 | 题目要求输出每项，对照结果文件逐项找 | 题目要「最优路径+总耗时」，结果只有总耗时＝漏输出 |
| A3 | 限定条件（范围/时段/频段/容量）在代码中搜常量/判断 | 代码里搜不到对应条件＝约束没进模型 |
| A4 | 单位量纲：题目 m vs 代码 km、min vs h，转换系数核对 | 系数错 1000/60 倍＝结果全错（查一遍大概率能抓出） |
| A5 | 模型假设 vs 实现：假设线性，代码里有没有非线性项；假设忽略摩擦，代码里有没有摩擦项 | 假设与实现违背＝论文写的和算的不是一回事 |
| A6 | 代码读取的文件是否都在题目附件/项目范围内 | 读到外部数据文件＝私加数据，须向用户确认（取消评奖风险） |
| A7 | 随机种子是否固定（复现清单.md 声明的 SEED，代码里实际 set 了没） | 没固定＝结果不可复现，评委复跑对不上 |
| A8 | 挑 2-3 个关键数字，用题目极限情境（最小/最大输入）心算/手算量级 | 量级差 10 倍以上＝bug，别急着跑 |

## B. 代码 vs 论文（5 条）

| # | 怎么查 | 查到什么值得怀疑 |
|---|---|---|
| B1 | 论文每张表/图的关键数字，在 03_qN_results.md/输出文件找到同值（抽查 ≥5 处） | 数值对不上＝论文错报/抄错/口径不一致 |
| B2 | 论文说的模型/方法与代码实现一致 | 论文写遗传算法，代码是贪心＝论文一套代码一套 |
| B3 | 论文「参数取值」（如 α=0.3）= 代码集中配置区的值 | 不一致＝论文参数抄错 |
| B4 | 论文「图 X」对应的图文件，能对上代码包里某个 fig_*.m/.py 及其数据 | 对不上＝图表可能用了别处数据 |
| B5 | 论文「提升 XX%」等百分比表述，回代码/输出文件验算 | 算不出＝夸大数据或口径不对（百分比是最常见的错报） |

## C. 执行与结论

- 每条结论三选一：**通过 / 有疑问 / 不通过**；有疑问与不通过必须写进 checkpoint `code_review` 段（问题+位置）
- **不通过 → Phase 3 不通过**：回改 → reviewer 重审（产物变更后旧审查失效）→ 人工检查重点复查改动处
- 全部通过 → 进入 Phase 4（此门禁不过不得进入写作）
- 备份位：检查完成后备份一次项目目录（Phase 0 确认的备份位置）
